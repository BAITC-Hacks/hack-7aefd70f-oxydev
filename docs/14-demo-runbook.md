# Qadam AI: чек-лист перед показом

## За 20 минут до выступления

1. Запустите Docker Desktop.
2. В каталоге проекта выполните `docker compose up -d --build`.
3. Если порт 8000 занят, в текущей PowerShell-сессии выполните
   `$env:QADAM_PORT='8765'`, затем повторите команду запуска.
4. Откройте `http://127.0.0.1:8000` или выбранный порт.
5. Проверьте `python scripts/demo_smoke.py`. Для порта 8765 сначала установите
   `$env:QADAM_BASE_URL='http://127.0.0.1:8765'`.
6. Не используйте реальные ответы кандидатов без согласованного правового
   основания. Три кнопки-примера содержат вымышленные ответы.
7. Для автоматической проверки нового кандидатского пути при запущенном Docker
   выполните в каталоге `web`: `npm run test:e2e`. Шесть сценариев проверяют
   EN/RU передачу и ручную проверку, ссылку на видео, локальную запись голоса
   и видео, а также отсутствие горизонтального переполнения на узком экране.
   На Windows требуется установленный Chrome; медиа в тестах создаются
   виртуальной камерой и микрофоном браузера; серверный pilot workflow —
   отдельными API-тестами.

## Сценарий на 90 секунд

Стартовый экран — интерактивный путь кандидата на английском языке; переключатель EN / KK / RU доступен на каждом шаге. Выберите текст, голос или видео. Для быстрого сквозного показа выберите «Write», затем «Use a fictional example», пройдите вымышленную командную ситуацию, объясните выбор одной фразой, подтвердите согласие и откройте кабинет комиссии. Прохождение получает код `QDM-…`, сохраняется на локальном сервере и появляется в очереди. Для существующего видео можно указать HTTPS-ссылку: Qadam хранит ссылку, но не скачивает и не анализирует ролик. Загруженная или записанная запись до 30 МБ сохраняется в локальном пилотном контуре. Русский текст поступит на экспериментальный анализ; английский/казахский текст и аудио/видео остаются материалом ручной проверки без непроверенного численного балла. Для прямого входа нажмите «Reviewer workspace». Используйте только вымышленные истории без личных данных.

1. На экране «Обзор» выберите «Конкретный пример лидерства»: откроется рабочее место и
   автоматически выполнится разбор.
2. Покажите «Приоритетно рассмотреть на интервью», ATOLA 5/5 и цитаты.
3. Покажите, что итоговый уровень считает модель, а не LLM, и рядом видна
   версия артефакта.
4. Подтвердите маршрут или измените его с конкретной причиной; покажите запись
   в журнале. Это ещё не решение о поступлении.
5. Откройте «Развёрнутый ответ без подтверждений»: подробная формулировка
   сама по себе не означает высокий уровень компетенции.
6. Нажмите «Проверить на предвзятость»: меняется только фоновый признак, балл
   почти неизменен.
7. Завершите: «Это решение для калибровки комиссии, не автоматический отказ.
   Следующий шаг — закрытая методология и экспертная валидация».

## Если Groq не отвечает

Система автоматически переключится на `heuristic-fallback`. Для демо это
допустимо, но нужно честно проговорить, что локальный разбор слабее LLM.
Проверенные примеры работают и без ключа.

## Если приложение не открывается

- `docker compose ps` — контейнер должен быть в состоянии `Up`.
- `docker compose logs --tail 80` — ищите ошибку обучения или занятого порта.
- Если Docker недоступен: `powershell -ExecutionPolicy Bypass -File .\run.ps1`.
- Если интернет пропал: ключ не требуется, приложение работает локально после
  установки зависимостей.

## Что не заявлять как готовое

- Девять компетенций: реально реализована одна.
- Подтверждённая точность на поступающих: текущая валидация синтетическая.
- Реальные аккаунты и роли: ещё не внедрены. Есть лишь учебный append-only
  журнал действий над вымышленными кейсами.
- Полноценный казахский UI: ещё не внедрён.
- Серверная обработка PDF/DOCX/видео: сейчас API анализирует только текст. Кандидатский экран сохраняет аудио/видео в локальном пилотном хранилище и передаёт его комиссии, но не расшифровывает и не анализирует запись.
- Публичный production-доступ: требуется защищённый хостинг, HTTPS,
  аутентификация, управление сроками хранения и юридическое согласование.

## После показа

Остановите контейнеры `docker compose down`. Именованные тома с моделью и
кэшем синтетического корпуса останутся; `down` без `-v` их не удаляет.
