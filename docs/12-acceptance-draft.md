# Черновик критериев приёмки пилота

Это темы для согласования, а не уже обещанные значения. Числа в квадратных
скобках должен утвердить заказчик после reference set.

## Основной сценарий

**Given** оператор передал разрешённый текст ответа на русском или казахском,
**When** Qadam AI завершил анализ,
**Then** оператор получает предварительный уровень, уверенность, покрытие ATOLA,
проверяемые цитаты и вопросы для интервью; решение можно подтвердить или
переопределить с обязательной причиной.

## Исключение 1: недостаточно доказательств

**Given** ответ слишком короткий, противоречивый или не содержит нужных
элементов, **When** система не достигает согласованного порога,
**Then** она не показывает уверенный уровень, а отправляет случай в ручную
очередь и указывает, чего не хватает.

## Исключение 2: внешний AI недоступен

**Given** внешний API недоступен или превысил таймаут, **When** приходит запрос,
**Then** система явно маркирует локальный fallback, не теряет запрос и не
подменяет результат облачного извлечения незаметно для оператора.

## Метрики для согласования

- weighted kappa с экспертным консенсусом ≥ `[значение]`;
- recall сильного класса ≥ `[значение]`, если его пропуск — главная цена ошибки;
- доля ручной очереди ≤ `[значение]`, без ухудшения recall;
- все показанные цитаты дословно существуют во входном ответе: 100%;
- метрики публикуются отдельно для RU, KK и code-switching;
- разрыв ключевой метрики между согласованными группами ≤ `[значение]`;
- p95 latency ≤ `[значение]` секунд при `[нагрузка]`;
- 0 потерянных запросов и понятный статус при отказе внешнего API;
- 100% решений и override имеют версию модели, время, пользователя и причину;
- удаление данных выполняется в согласованный срок и проверяется тестом.

## Что нужно измерить «до → после»

- медианное время первичного разбора одного кандидата;
- разброс оценок между интервьюерами;
- доля случаев без доказательства/цитаты;
- число кандидатов, возвращённых на повторную проверку;
- нагрузка комиссии и доля ручной очереди.
