## Короткие ответы жюри

### Почему 95,2%?

Это только синтетический holdout, а не качество на реальных кандидатах. Сейчас метрика подтверждает работоспособность контура; следующий шаг — независимая экспертная валидация.

### Почему LLM не ставит балл напрямую?

Прямая LLM-оценка менее воспроизводима и смешивает факты с суждением. В Qadam LLM только извлекает, а классификатор выдаёт проверяемую оценку.

### Как проверяется предвзятость?

Фоновые данные не используются как признаки. Дополнительно мы меняем в ответе только один атрибут и измеряем дельту. Говорить нужно не «bias исключён», а «bias измеряется и контролируется».

### Может ли система отказать кандидату?

Нет. Она даёт предварительный сигнал и вопросы для интервьюера. Решение и ответственность остаются у комиссии.

### Почему только одна компетенция?

Это полный вертикальный срез: данные, модель, объяснение, fairness, API и интерфейс. Теперь его можно расширять вместе с владельцами методологии.

## Перед подключением

1. Открыть финальную презентацию `Qadam_AI_Mock_Demo_Day_1_FINAL.pptx`.
2. Запустить `powershell -ExecutionPolicy Bypass -File .\run.ps1`.
3. Открыть адрес из терминала, обычно `http://127.0.0.1:8765`.
4. Нажать `Ctrl+F5` и один раз проверить весь demo-flow.
5. Закрыть `.env`, терминалы с ключами, уведомления и лишние окна.
6. Если Groq нестабилен, использовать офлайн-режим: встроенный пример работает детерминированно.
