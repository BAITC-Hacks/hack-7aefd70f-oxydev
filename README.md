# Qadam AI — AI Leader ID для inVision U

**GovTech Camp 2026 · Кейс inVision U · Команда Oxydev (соло) · Тимур Камараев**

> Қадам — «шаг». Мы оцениваем не точку, в которой кандидат находится, а шаги, которые он сделал.

---

## Позиционирование в одну фразу

**Мы строим веб-сервис для короткого ответа кандидата и доказательного рассмотрения комиссией, а не автоматического судью.**

Кандидат проходит короткий интерактивный путь на английском, казахском или русском: выбирает текст, голос или видео, рассказывает одну историю и отвечает на ситуационную мини-сцену. После явного согласия прохождение получает анонимный код и сохраняется в локальном пилотном контуре. Комиссия видит исходные слова/запись и обоснование выбора. Экспериментальный анализ одной компетенции помогает сопоставлять русский текст с рубрикой и требует, чтобы каждый вывод опирался на цитату. Ситуационная сцена пока не оценивается баллом.

Заказчик сам сформулировал приоритет на последнем слайде своей презентации:

> «Решение, которое даёт высокий AUC и не может объяснить ни одного своего балла, мы не сможем поставить в приём.»

Цель — полезное и проверяемое решение: точность необходимо доказать на экспертной разметке, а каждый вывод должен быть объясним.

---

## Что делает MVP

Сейчас реализована одна компетенция — «Лидерские способности». Точная методология заказчика, веса и пороги ещё запрошены и не подтверждены. На вход экспериментального анализа подаётся русский текст ответа; на выход:

- **уровень** weak / normal / strong с калиброванными вероятностями;
- **разбор ATOLA** — пять элементов, под каждым дословная цитата из ответа или пометка «не прозвучало»;
- **сработавшие индикаторы BARS** — формулировка индикатора и цитата-якорь под ней;
- **вклад каждого признака в балл** — арифметика логита, а не пересказ модели;
- **подсказки интервьюеру** — какие элементы копнуть и какими вопросами методологии;
- **черновик обратной связи кандидату** — что развивать;
- **проверка на предвзятость** — тот же ответ с изменённым фоновым признаком и Δ балла рядом.

Ключевое архитектурное решение: **LLM извлекает и цитирует, уровень ставит обученный классификатор на детерминированных признаках.** Решение целиком на промптах не засчитывается по п. 10.3 общего ТЗ GovTech, и балл, который меняется между запусками, комиссия защитить не сможет.

Формулировка для питча: «LLM у нас не судья, а стенографист. Судит обученная модель на признаках, которые можно предъявить».

## Как запустить

Windows PowerShell (основной вариант для Mock Day):

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Linux / WSL / Git Bash:

```bash
./run.sh
```

Из чистого окружения через Docker Desktop:

```bash
docker compose up --build
```

После первого обучения откроется `http://127.0.0.1:8000`. Модель и разрешённый
кэш синтетического корпуса находятся в именованных Docker volumes; `.env` в
образ не копируется.

Стартовая страница — путь кандидата с английским языком по умолчанию и переключением EN / KK / RU. Доступны текст, запись/выбор аудио или видео, HTTPS-ссылка на уже существующее видео и короткая ветвящаяся ситуация. После согласия ответ и запись до 30 МБ сохраняются на том же локальном сервере; внешнюю HTTPS-ссылку Qadam хранит, но не скачивает и не анализирует. Автоматической транскрипции пока нет. После отправки прохождение получает код `QDM-…` и появляется в очереди комиссии. Автоматический балл показывается только для русского текста как результат экспериментальной модели на синтетических данных. Английский и казахский ответы, а также аудио/видео передаются для ручного рассмотрения без численного балла. Используйте только вымышленные или обезличенные истории. Это не утверждённая стадия приёма; формат, сроки хранения и доступы нужно согласовать с inVision U.

Интервьюер может зафиксировать маршрут, дословное свидетельство/таймкод и комментарий, а также скачать JSON-отчёт. Для пилотного прохождения решение сохраняется в append-only журнале SQLite и остаётся после обновления страницы; три синтетических примера продолжают жить в отдельном учебном журнале без исходных текстов. Сквозной браузерный тест: `cd web`, затем `npm run test:e2e` при запущенном локальном сервере и установленном Chrome.

По умолчанию Docker-порт привязан только к `127.0.0.1`. Не публикуйте сервер
без защиты. Для закрытого онлайн-демо задайте длинный `QADAM_DEMO_PASSWORD`
в `.env` и используйте HTTPS reverse proxy. HTTP Basic — временная защита
демо, а не готовая ролевая модель для данных кандидатов.
Если порт 8000 занят, перед запуском Docker установите `QADAM_PORT=8765` —
адресом станет `http://127.0.0.1:8765`.

В интерфейсе есть учебная очередь из трёх **вымышленных** кандидатов: откройте
карточку, запустите анализ, подтвердите или измените маршрут рассмотрения и
посмотрите историю действий. Для изменения маршрута требуется причина.
Журнал хранит только ID синтетического кейса, маршрут, имя демо-пользователя,
причину и версию модели; текст ответа не сохраняется. Это прототип workflow,
не production-хранилище заявок и не полноценная система ролей.

Откроется `http://127.0.0.1:8000`. Скрипт идемпотентный: ставит зависимости, генерирует корпус, обучает модель, собирает фронт и поднимает сервер, пропуская то, что уже сделано.

Ключ к LLM **не нужен**: без него слой извлечения работает детерминированным разбором по маркерам речи. Для более качественного разбора произвольных ответов создайте `.env` по `.env.example` и добавьте бесплатный ключ Groq:

```dotenv
GROQ_API_KEY=gsk_...
QADAM_GROQ_MODEL=openai/gpt-oss-20b
```

Порядок auto-режима: Groq → Anthropic → офлайн-эвристика. При сетевой ошибке, невалидном JSON или лимите облачного API запрос автоматически завершается эвристикой, поэтому демонстрация не падает. Anthropic остаётся опциональным:

```bash
export ANTHROPIC_API_KEY=...
```

Пошагово, если нужно по частям:

```bash
python3 -m pip install -r requirements.txt
python3 -m qadam.data.generate     # корпус: 140 ответов + 40 контрфактических пар
python3 -m qadam.core.extract --corpus   # прогрев кэша извлечения
python3 -m eval.train              # обучение, метрики, eval/report.md
python3 -m qadam.core.fairness     # только контрфактический аудит
python3 -m uvicorn qadam.api.main:app --port 8000
cd web && npm install && npm run dev     # фронт в режиме разработки, порт 5173
```

Полезные ключи: `python3 -m eval.train --embeddings none|char_tfidf|sbert`, `--with-sbert-ablation`, `python3 -m qadam.data.generate --backend llm`, `python3 -m qadam.core.extract --backend groq --text "..."`.

Многоязычные эмбеддинги ставятся отдельно, потому что тянут torch: `pip install -r requirements-embeddings.txt`.

## Архитектура

```
Ответ кандидата
  ↓
Слой 1. ИЗВЛЕЧЕНИЕ — qadam/core/extract.py
  LLM (temperature=0, строгий JSON) размечает ATOLA, выписывает
  индикаторы и маркеры конкретности. Каждая цитата проверяется на дословное
  вхождение в текст; не найденная дословно — отбрасывается. Уровня и балла
  в схеме нет.

  Для запросов API дисковый кэш отключён: структура извлечения содержит
  дословные цитаты и может включать персональные данные. Кэш используется
  только при работе с разрешённым синтетическим корпусом.
  ↓
Слой 2. ПРИЗНАКИ — qadam/core/features.py
  21 детерминированный признак: покрытие ATOLA, индекс конкретности, индекс
  «воды», соотношение «я»/«мы», дельта траектории, срабатывания индикаторов,
  длина как контрольный признак. Никакого обращения к LLM.
  ↓
Слой 3. СКОРИНГ — qadam/core/model.py
  Логистическая регрессия на признаках плюс текстовые векторы, три класса,
  калибровка вероятностей, стратифицированное разбиение.
  ↓
Слой 4. ОБЪЯСНЕНИЕ — qadam/core/explain.py
  Вклад признаков, цитаты-якоря, подсказки интервьюеру, черновик обратной связи.
```

Сбоку: `qadam/core/fairness.py` — контрфактический аудит; `eval/` — обучение, baseline, отчёт.

## Данные

Реальных обезличенных оценок до этапа внедрения нет (docs/01-context.md §6), поэтому корпус синтетический и порождён из опубликованной рубрики.

- 120 ответов, по 40 на уровень, с балансом по длине, стилю речи, языку, домену истории, региону и полу говорящего;
- 20 «шумовых» ответов: слабое содержание в отполированной речи и сильное содержание в корявой. Самые ценные примеры корпуса: они проверяют, не путает ли модель красноречие с потенциалом;
- 36 из 120 ответов собраны из блоков двух соседних уровней. На «чистом» корпусе любая модель показывает единицу, и такая метрика ничего не значит;
- 40 контрфактических пар: одно и то же содержание, изменён ровно один фоновый признак — село/город, язык, отполированность речи, род говорящего.

**Правило генерации:** в порождающий промпт передаются только дословные формулировки индикаторов нужного уровня. Слова «слабый», «сильный», «хороший кандидат» в промпт не попадают — иначе метка стала бы пересказом суждения модели, а не свойством текста. Для LLM-бэкенда это проверяется автоматически, для шаблонного обеспечено конструкцией.

Синтетика — не персональные данные: это позволяет безопасно показать механизм, но не доказывает работу на реальных поступающих. Переход к реальным данным потребует отдельного согласования, защищённой инфраструктуры, сроков хранения, контроля доступа, аудита и экспертной валидации; простой заменой файла корпуса этого сделать нельзя.

## Метрики

Полный отчёт генерируется автоматически: [`eval/report.md`](eval/report.md), числа машинно-читаемо — `eval/metrics.json`. Снимок текущего прогона:

| Что меряем | Значение |
|---|---:|
| Accuracy на отложенной выборке | 0.952 |
| Quadratic weighted kappa | 0.968 |
| Baseline «только длина ответа» | 0.357 |
| Baseline «случайно по априорному распределению» | 0.335 |
| Без признаков-индикаторов (консервативная оценка) | 0.881 |
| Точность разметки ATOLA против плана генератора | 0.949 |
| **Максимальный сдвиг балла от фонового признака (95-й перцентиль)** | **0.100 ступени уровня при пороге 1.0** |

Тесты устойчивости: перефраз не меняет уровень ни в одной паре, ИИ-полировка не поднимает балл, удаление Outcome и Application роняет его.

## Ограничения и этические границы

Это не оговорки мелким шрифтом, а часть решения.

1. **Wounded leadership и «Ценности» не скорятся.** Модель отмечает, что тема прозвучала, и предлагает уточняющие вопросы методологии. Балл по этим блокам ставит человек. Причина: чувствительные данные о несовершеннолетних, этическая несостоятельность автоматической оценки «правильности» переживания травмы и прямой вред от ошибки.
2. **Признак «текст похож на сгенерированный» не снижает балл.** Никогда. Он запускает уточняющие вопросы о деталях собственной истории кандидата. Детекторы ИИ-текста систематически чаще ошибаются на неносителях языка — то есть штрафовали бы ровно тех, ради кого создан университет.
3. **Фоновые признаки не входят в модель.** Ни регион, ни тип школы, ни язык ответа, ни доход семьи, ни пол. Это проверяется не обещанием, а двумя вещами: утверждением в коде (`assert_no_background_features`) и контрфактическим аудитом на 40 парах.
4. **Траектория меряется внутри истории самого кандидата** — дельта «было → стало» из его же Outcome и Application. Логика «он из села, значит его результат ценнее» — это прямо запрещённый п. 6.3 скоринг по социально-экономическим данным.
5. **Система не принимает решений о поступлении** и не отказывает кандидату. Она приоритизирует, объясняет и выравнивает шкалу.
6. **Числа получены на синтетике.** Они измеряют согласие с рубрикой, а не с решением приёмной комиссии. Часть признаков разделяет словарь с генератором — поэтому в отчёте отдельной строкой приведён результат без этой группы признаков.
7. **Слой извлечения без ключа — эвристический.** Рабочий путь — LLM с проверкой дословности цитат.
8. **Слепая ручная разметка ещё не внесена.** Файл для неё генерируется (`qadam/data/corpus/blind_sample.jsonl`), согласие человека с рубрикой в текущие метрики не входит.

## Структура репозитория

```
qadam/
  data/rubric.py        BARS-индикаторы трёх уровней и ATOLA, дословно из методологии
  data/generate.py      генератор корпуса, шумовых примеров и контрфактических пар
  data/corpus/          корпус и файл для слепой разметки (в git намеренно)
  data/counterfactual/  контрфактические пары
  core/extract.py       слой извлечения: LLM или детерминированный разбор
  core/features.py      признаки, без LLM
  core/model.py         обучение, инференс, калибровка
  core/explain.py       вклад признаков, цитаты, подсказки, обратная связь
  core/fairness.py      контрфактический аудит
  api/main.py           FastAPI: /analyze, /counterfactual, /examples, /health
eval/
  train.py              обучение и полный отчёт
  baselines.py          три baseline
  report.md             отчёт, генерируется автоматически
  metrics.json          те же числа машинно-читаемо
web/                    Vite + React + TypeScript, демо-кабинет из 4 разделов
docs/                   контекст кейса, спецификация, планы
run.sh                  запуск одной командой
run.ps1                 запуск одной командой в Windows
```
