# Oxydev / Qadam AI

Qadam AI — веб-сервис для отбора абитуриентов inVision U: кандидат отвечает текстом, голосом или видео, а комиссия получает структурированный разбор с цитатами и самостоятельно принимает итоговое решение.

**Трек:** inVision U Case  
**Команда:** Oxydev  
**Участник:** Тимур Камараев  
**Работающий сервис:** https://oxydev.govtech-kz.com

## Задача

Кандидаты отличаются не только опытом, но и умением рассказывать о себе. Красивое эссе может не содержать подтверждённых действий, а короткий или неидеально сформулированный ответ может скрывать сильный лидерский опыт.

Qadam AI помогает приёмной комиссии:

- собирать ответы кандидатов в удобном формате;
- находить конкретные действия, результаты и выводы;
- подтверждать каждый вывод дословной цитатой;
- готовить уточняющие вопросы для интервью;
- сохранять решение комиссии и его обоснование.

Сервис не принимает решение о поступлении вместо человека.

## Что реализовано

### Анкета кандидата

- интерфейс на английском, казахском и русском языках;
- текстовый, голосовой и видеоформаты ответа;
- запись с камеры или микрофона непосредственно в браузере;
- загрузка готового файла или ссылки на видео;
- короткая история из опыта кандидата;
- интерактивная командная ситуация;
- согласие перед сохранением ответа;
- адаптация под смартфоны.

### Кабинет комиссии

- единая очередь кандидатов;
- автоматический разбор поддерживаемого текстового ответа;
- предварительная оценка компетенции «Лидерские способности»;
- структура ATOLA: Action, Thinking, Outcome, Learning, Application;
- поведенческие индикаторы BARS;
- дословные цитаты из исходного ответа;
- вопросы для следующего интервью;
- выбор следующего шага человеком;
- сохранение причины решения и истории проверок;
- печать и сохранение отчёта в PDF.

### Проверяемость

- одинаковый вход даёт воспроизводимый результат;
- цитаты проверяются по исходному тексту;
- регион, тип школы и доход семьи не используются как признаки оценки;
- реализован контрфактический тест фоновых характеристик;
- сохраняются версии оценки и правила, по которым выполнен разбор;
- итоговое решение всегда остаётся за комиссией.

## Как работает решение

1. Кандидат открывает анкету и выбирает язык и формат.
2. Рассказывает о реальном случае и отвечает на командную ситуацию.
3. Ответ появляется в кабинете комиссии.
4. Сервис выделяет факты, цитаты, пробелы и вопросы для интервью.
5. Комиссия проверяет исходный материал и выбирает следующий шаг.
6. Решение и обоснование сохраняются в истории.

## Технологии

- React, TypeScript, Vite;
- Python, FastAPI, Pydantic;
- scikit-learn и собственная модель предварительной оценки;
- NLP и LLM-извлечение через Groq с автономным резервным режимом;
- SQLite для очереди и журнала решений;
- Docker Compose;
- Playwright и unittest;
- VPS и HTTPS для публичного стенда.

## Архитектура

```text
Кандидат
   │
   ▼
React-интерфейс ──► FastAPI ──► очередь ответов
                              │
                              ├─► извлечение ATOLA и цитат
                              ├─► воспроизводимая ML-оценка
                              ├─► вопросы для интервью
                              └─► журнал решений комиссии
```

LLM используется для структурирования материала и поиска цитат. Численная рекомендация формируется отдельным воспроизводимым слоем. Любой вывод можно проверить по исходному ответу, а комиссия может подтвердить или изменить предложенный следующий шаг.

## Запуск через Docker

```bash
docker compose up --build
```

После запуска сервис доступен по адресу `http://localhost:8000`.

Переменные окружения перечислены в `.env.example`. Для автономного режима внешний API-ключ не требуется. Для LLM-извлечения можно указать `GROQ_API_KEY`.

## Локальный запуск в Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```
